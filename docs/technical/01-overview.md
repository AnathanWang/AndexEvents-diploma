# 1. Обзор системы

## 1.1 Назначение

**Andex Events** — платформа для поиска событий и социального матчинга пользователей в контексте событий и геолокации.

Функциональные области реализации:

| Область | Описание |
|---------|----------|
| События | Создание, список/афиша, карта (Yandex MapKit на клиенте), участие, модерация статусов |
| Профиль | Регистрация/онбординг, данные пользователя, геолокация, отчёты о нарушениях |
| Матчинг | Свайпы, лайк/дизлайк/super-like, взаимные мэтчи, входящие лайки (отдельный Go-сервис) |
| Медиа | Загрузка изображений в MinIO, публичные URL для отображения в приложении |

Идентификация конечного пользователя выполняется через **Firebase Authentication**. Backend принимает **Firebase ID Token** в заголовке `Authorization: Bearer <token>` на защищённых маршрутах.

Каноничный файл окружения разработки: `deployments/docker/docker-compose.yml`.

## 1.3 Стек технологий (актуальный)

| Слой | Технология | Примечание |
|------|------------|------------|
| Mobile | Flutter (Dart), SDK из `pubspec.yaml` | BLoC, пакет `http` для REST |
| Шлюз | Traefik (образ `traefik:latest`) | Docker provider, entrypoint `web` :80 |
| Backend (domain) | Java 21, Spring Boot 3.3.x | Три сервиса в `services-java/` |
| Backend (matching/uploads) | Go 1.23+, Gin, jackc/pgx | `services/match-service`, `services/upload-service` |
| Общий Go-код | `shared/pkg/...` | В т.ч. клиент Firebase для Go |
| СУБД | PostgreSQL 16, расширение PostGIS | Образ `postgis/postgis:16-3.4` |
| Кэш | Redis 7 | Поднимается в compose; фактическое использование в коде сервисов нужно проверять по репозиторию |
| Объектное хранилище | MinIO | API :9000, консоль :9001 |
| Auth (внешний) | Firebase Authentication | JWT проверяется на backend |

## 1.4 Границы ответственности сервисов

- **auth-service** — валидация токена и привязка Firebase UID к внутреннему `userId` (чтение из `users."User"`).
- **users-service** — жизненный цикл профиля пользователя в схеме `users`.
- **events-service** — события и участники в схеме `events`.
- **match-service** — действия матчинга и запросы списков мэтчей (отдельная предметная область на Go).
- **upload-service** — запись файлов в MinIO и выдача по `/uploads/...`.

Подробности по каждому сервису: [05-backend-java.md](./05-backend-java.md), [06-backend-go.md](./06-backend-go.md).
