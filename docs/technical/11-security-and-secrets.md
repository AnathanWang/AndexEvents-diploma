# 11. Безопасность и секреты

## 11.1 Секреты вне Git

Каталог **`secrets/`** в корне репозитория предназначен для локальных файлов и **не должен коммититься**. Типичное содержимое (см. `docs/setup.md`):

| Файл | Назначение |
|------|------------|
| `firebase-service-account.json` | Firebase Admin SDK для Go-сервисов и серверной логики |
| `yandex_mapkit_api_key.txt`, `yandex_geocode_api_key.txt` | Ключи для скриптов/локальной разработки |
| прочие `.txt` / ключи | Legacy или вспомогательные секреты |

В Docker Compose Go-сервисы монтируют только **`secrets/firebase-service-account.json`** в контейнер.

## 11.2 Клиентские секреты

- Конфигурации Firebase для Android/iOS (`google-services.json`, `GoogleService-Info.plist`) содержат открытые идентификаторы приложения; доступ к админским операциям через них невозможен без серверных ключей.
- Ключи Yandex передаются при сборке через **`--dart-define`**, не вшиваются в публичный репозиторий.

## 11.3 Транспорт

- В production ожидается **HTTPS** между клиентом и API (см. боевой hostname в `AppConfig`).
- В локальной разработке часто используется HTTP на порту 80 (Traefik) — допустимо только в доверенной сети.

## 11.4 Авторизация на API

- Защищённые маршруты требуют валидный **Firebase ID Token**.
- Публичные маршруты (например часть `GET /api/events`, выдача статики `/uploads/...`) должны быть явно перечислены в обзоре API; при добавлении новых публичных эндпойнтов нужно проверять отсутствие утечки персональных данных.

## 11.5 Загрузка файлов

- Проверка типа файла: расширение + sniff байтов + ограничение размера (см. upload-service).
- Имена файлов генерируются сервером (случайный суффикс), чтобы избежать коллизий и предсказуемых путей.
